# Video demonstration workload (architecture §12)

## Files and provenance

| File | SHA-256 | Provenance and license |
|---|---|---|
| `sample.mp4` | see `SHA256SUMS` | **Synthetic.** Generated by `generate.sh` from FFmpeg's built-in `testsrc2` pattern: 10 s, 1280×720, 20 fps, H.264 (libx264, CRF 28, yuv420p), no audio, about 1.5 MB. It contains no third-party media and is project-owned and redistributable. Generation is byte-reproducible in the pinned harness image `dag-ms2/harness:0.2.0` (FFmpeg 6.1.1): two independent runs gave the same SHA-256. |
| `fixture.srt` | see `SHA256SUMS` | **Fixture subtitles**, hand-written by the project. They are not produced by speech recognition, and no transcription or paid API is used. The `fixture_subtitles` operation copies this file to the task output, and the published manifest labels it `"fixture_subtitles": true`. |

Nothing is downloaded at run time: the demo and tests upload these two committed files to the artifact store.

The checkpoint's earlier `sample.mp4` was also a synthetic FFmpeg 6.1 clip (same size, rate and duration), but its generation command was never recorded. At Step 9 it was replaced by the output of `generate.sh`, so its provenance is now exact.

## DAG

`tests/harness/api.py: video_manifest()` builds this graph. `tests/harness/demo.py` writes the same manifest to `manifest.json` in the demo output.

| Task | Parents | Operation | Output |
|---|---|---|---|
| inspect | none | `video_inspect`: ffprobe JSON | `metadata` |
| transcode720 | inspect | `video_transcode` height=720 | `video` (MP4) |
| transcode360 | inspect | `video_transcode` height=360 | `video` (MP4) |
| thumbnail | inspect | `video_thumbnail`: first frame | `image` (PNG) |
| subtitles | inspect | `fixture_subtitles`: copy the SRT | `subtitles` |
| publish | all four branches | `video_publish` | `manifest`: accepted references for the 720p and 360p videos, the thumbnail and the subtitles, plus ffprobe metadata for both videos |

The worker runs FFmpeg with one thread, a fixed codec and preset (libx264 `veryfast`, CRF 28), a 30 s local timeout and checked exit codes. "Publishing" means producing an artifact manifest; there is no video platform.

## Reproduce

- Automated check: `pytest tests/integration/test_system.py::test_video_pipeline`, inside the harness via `deploy/harness/run.sh`.
- Live demo against a running deployment: `make up`, then `make demo`. Outputs are written to `results/demo/<timestamp>/`.
- Verify the inputs: `sha256sum -c workloads/video/SHA256SUMS`, run from inside `workloads/video`.
